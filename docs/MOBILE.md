# Mobile layer

## What it does

On a phone-shaped LAN browser the plugin restyles DSH's own layout into a drawer,
a full-width conversation and a bottom bar. It is a layer over someone else's DOM,
which is the whole risk, so the coupling is confined and probed.

## Blank header

A new/blank session has no title and no header actions: the only control is the
drawer toggle. On those headers the toggle moves to the right edge (the
`headerBlank` / `headerSessionless` class on DSH's header), so it does not sit
alone in the top-left corner. Conversation headers keep it on the left, next to
the title.

## Workspace picker

DSH's native picker is an OS dialog on the host, which a phone cannot answer.
On a LAN page the client swaps <code>uiWorkspace.pickDirectory</code> for the
plugin's own dialog (plain DOM, one level at a time, new folder, select the
current directory). Listings come from <code>/api/remote/browse</code>, which
uses Node's stdlib on the host. The <code>127.0.0.1</code> window never takes
the branch, so the desktop keeps the native chooser. The patch lives in
<code>src/client/picker/install.js</code> and is disposed with the plugin.

## Safe areas

The viewport meta is applied per platform, not once for everyone:

- **iOS** keeps `viewport-fit=cover`; the stylesheet reads `env(safe-area-inset-top)`
  and `env(safe-area-inset-bottom)` so the notch and the home indicator do not
  cover the header or the bottom bar.
- **Android** deliberately drops `viewport-fit=cover`. Chrome on Android reports
  `env(safe-area-inset-top)` as `0` even though the status bar overlays the page,
  so keeping cover puts the first row underneath the clock and the battery icons.
  Without cover the browser insets the page itself.
- **Native shell** (android/) targets SDK 36, and Android 15 enforces edge-to-edge.
  The app calls `WindowCompat.setDecorFitsSystemWindows(false)` and pads each
  activity root by the system-bar insets, so the WebView starts below the status
  bar and ends above the navigation bar.

If a future DSH upgrade changes the header, check the status bar on both an iPhone
and an Android phone before touching this rule.

## Anchor contract

Every selector the layer touches lives in `src/client/mobile/anchors.js` with an
id, a selector, a purpose and a required flag. Nothing else in the client may
hard-code a DSH selector.

| Kind | Example | Required | Why |
|---|---|---|---|
| frame and column data attributes | `[data-shell-bottom]`, `[data-sidebar-right-panel]` | yes for the frame | structural; the layer cannot work without them |
| feature data attributes | `[data-composer-input]`, `[data-row-key]`, `[data-files-path]` | no | one gesture degrades |
| hashed CSS-module fragments | `[class*="_sidebarCol"]` | never | generated by DSH's build; may be renamed without notice |

The last row is the reason this document exists. Those class names are not an
interface. They are present in the shipped 0.2.1-rc.2 runtime, absent from the
0.1.7-alpha.2 copies that also exist on disk, which is exactly why the gate probes
the live document instead of reading a package version.

## Gate

`waitForShell` runs one mutation observer plus a rAF coalescer (bounded at 2 s)
and then probes the table once:

- every required anchor present → the layer installs;
- anything required missing → **the layer does not install**: no `dshm-mobile`
  class, no bottom bar, no restyling. The desktop layout stays usable, one line is
  logged, and `<html data-dshm-caps="missing:…">` records why.

This is the difference between "the plugin needs an update" and "the phone is
unusable after a DSH upgrade".

## Debugging

| Symptom | Check |
|---|---|
| desktop layout on a phone | `document.documentElement.dataset.dshmCaps`; if unset, the page is not a remote origin (`isRemoteOrigin`) |
| bottom bar missing but layout is mobile | the `shell.bottom` slot was not declared by the running `dsh-client-ui-layout` |
| drawer does not open | `sidebarCol` anchor missing, or `ctx.get('layout').toggleSidebar` absent |
| no styling at all | the plugin bundle failed to load; check the console and `localStorage.dshRemoteDebug = '1'` |

Force a mode for development with `?dshm=mobile` or `?dshm=desktop`.

## When DSH changes

1. Run the phone page and read `data-dshm-caps`.
2. Update the affected row in `anchors.js` (and its `purpose` if the meaning
   changed).
3. `npm run build`, then `npm test` — the contract test asserts the table's shape
   and that no hashed selector is ever marked required.
